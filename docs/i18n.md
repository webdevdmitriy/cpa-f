# Интернационализация (i18n) с next-intl

## Обзор

В проекте используется [`next-intl`](https://next-intl.dev) v4 для локализации. Роутинг построен на сегменте `[locale]` в App Router — каждый язык имеет свой URL-префикс.

**Поддерживаемые языки:**

- `en` — English (по умолчанию)
- `ru` — Русский

**Примеры URL:**

```
/        → редирект на /en
/en      → главная на английском
/ru      → главная на русском
/en/...  → любой вложенный маршрут на английском
/ru/...  → любой вложенный маршрут на русском
```


## Конфигурация

### `src/i18n/routing.ts`

Определяет список локалей и локаль по умолчанию. Этот объект используется как в middleware, так и в layout.

```ts
import { defineRouting } from 'next-intl/routing'

export const routing = defineRouting({
  locales: ['en', 'ru'],
  defaultLocale: 'en'
})
```

Чтобы добавить новый язык — достаточно добавить его в массив `locales` и создать соответствующий файл в `messages/`.

---

### `src/i18n/request.ts`

Серверная конфигурация: для каждого запроса определяет локаль и загружает соответствующий файл переводов. Путь к этому файлу передаётся в плагин в `next.config.ts`.

```ts
import { getRequestConfig } from 'next-intl/server'
import { routing } from './routing'

export default getRequestConfig(async ({ requestLocale }) => {
  let locale = await requestLocale

  if (!locale || !routing.locales.includes(locale as (typeof routing.locales)[number])) {
    locale = routing.defaultLocale
  }

  return {
    locale,
    messages: (await import(`../../messages/${locale}.json`)).default
  }
})
```

---

### `middleware.ts`

Middleware перехватывает входящие запросы и выполняет редиректы/реврайты на основе локали. Например, `/` → `/en`, `/ru/about` остаётся как есть.

```ts
import createMiddleware from 'next-intl/middleware'
import { routing } from './src/i18n/routing'

export default createMiddleware(routing)

export const config = {
  // Применяется ко всем маршрутам, кроме статических файлов и служебных путей Next.js
  matcher: ['/((?!_next|_vercel|.*\\..*).*)']
}
```

---

### `next.config.ts`

Плагин `withNextIntl` настраивает Next.js для работы с серверными переводами (Server Components, статическая генерация).

```ts
import type { NextConfig } from 'next'
import createNextIntlPlugin from 'next-intl/plugin'

const withNextIntl = createNextIntlPlugin('./src/i18n/request.ts')

const nextConfig: NextConfig = {
  // ... остальные опции
}

export default withNextIntl(nextConfig)
```

### `src/app/[locale]/layout.tsx`

Корневой layout для всех локализованных страниц. Валидирует локаль из URL — если передан неизвестный язык, вызывает `notFound()`. Оборачивает дерево компонентов в `NextIntlClientProvider`, что делает переводы доступными в Client Components.

```tsx
import { NextIntlClientProvider, hasLocale } from 'next-intl'
import { notFound } from 'next/navigation'
import { routing } from '@/i18n/routing'

export default async function LocaleLayout({ children, params }) {
  const { locale } = await params

  if (!hasLocale(routing.locales, locale)) {
    notFound()
  }

  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider>{children}</NextIntlClientProvider>
      </body>
    </html>
  )
}
```

## Файлы переводов

Файлы переводов лежат в `messages/` и имеют структуру JSON с пространствами имён (namespace).

### `messages/en.json`

```json
{
  "HomePage": {
    "title": "Hi. Im title",
    "button": "partner up"
  }
}
```

### `messages/ru.json`

```json
{
  "HomePage": {
    "title": "Привет. Я заголовок",
    "button": "стать партнёром"
  }
}
```

**Соглашение по именованию namespace:** название совпадает с именем страницы или компонента (PascalCase). Например: `HomePage`, `AboutPage`, `Header`, `ContactForm`.

## Использование переводов в компонентах

### Server Component (рекомендуется)

```tsx
import { useTranslations } from 'next-intl'

export default function HomePage() {
  const t = useTranslations('HomePage')

  return (
    <main>
      <h1>{t('title')}</h1>
      <button>{t('button')}</button>
    </main>
  )
}
```

### Client Component

В Client Components `useTranslations` работает так же — переводы доступны благодаря `NextIntlClientProvider` в layout.

```tsx
'use client'

import { useTranslations } from 'next-intl'

export function SomeClientComponent() {
  const t = useTranslations('SomeNamespace')

  return <p>{t('someKey')}</p>
}
```

### Интерполяция переменных

```json
{
  "Greeting": {
    "hello": "Hello, {name}!"
  }
}
```

```tsx
t('hello', { name: 'Alex' }) // → "Hello, Alex!"
```

### Плюрализация

```json
{
  "Cart": {
    "items": "{count, plural, =0 {No items} =1 {One item} other {# items}}"
  }
}
```

```tsx
t('items', { count: 5 }) // → "5 items"
```

## Получение текущей локали

### В Server Component / Server Action

```ts
import { getLocale } from 'next-intl/server'

const locale = await getLocale() // 'en' | 'ru'
```

### В Client Component

```tsx
'use client'

import { useLocale } from 'next-intl'

export function LocaleDisplay() {
  const locale = useLocale() // 'en' | 'ru'
  return <span>{locale}</span>
}
```

## Переключение языка

Для переключения языка используйте стандартную навигацию Next.js — просто меняйте префикс URL. Для типобезопасной навигации можно создать обёртки через `createNavigation`:

```ts
// src/i18n/navigation.ts
import { createNavigation } from 'next-intl/navigation'
import { routing } from './routing'

export const { Link, redirect, usePathname, useRouter } = createNavigation(routing)
```

Тогда компонент переключения языка:

```tsx
'use client'

import { useLocale } from 'next-intl'
import { useRouter, usePathname } from '@/i18n/navigation'

export function LocaleSwitcher() {
  const locale = useLocale()
  const router = useRouter()
  const pathname = usePathname()

  const switchLocale = (newLocale: string) => {
    router.replace(pathname, { locale: newLocale })
  }

  return (
    <div>
      <button onClick={() => switchLocale('en')} disabled={locale === 'en'}>
        EN
      </button>
      <button onClick={() => switchLocale('ru')} disabled={locale === 'ru'}>
        RU
      </button>
    </div>
  )
}
```

## Добавление нового языка

1. Создать файл `messages/<код>.json` с теми же ключами, что в `en.json`
2. Добавить код языка в `src/i18n/routing.ts`:
   ```ts
   locales: ['en', 'ru', 'de']
   ```
3. Готово — middleware и layout подхватят новый язык автоматически.

---

## Добавление нового namespace (новой страницы/компонента)

1. Добавить ключи в каждый файл переводов:
   ```json
   // messages/en.json
   {
     "HomePage": { ... },
     "AboutPage": {
       "heading": "About us"
     }
   }
   ```
2. Использовать в компоненте:
   ```tsx
   const t = useTranslations('AboutPage')
   t('heading') // → "About us"
   ```

## Типизация переводов

next-intl поддерживает автодополнение и проверку ключей на этапе компиляции. Для этого создайте файл `src/types/next-intl.d.ts`:

```ts
import en from '../../messages/en.json'

type Messages = typeof en

declare global {
  interface IntlMessages extends Messages {}
}
```

После этого TypeScript будет ругаться на несуществующие ключи и подсказывать доступные.
